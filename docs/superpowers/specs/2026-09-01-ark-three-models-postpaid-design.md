# 火山方舟三个模型接入与 Seedream 后付费设计

日期：2026-09-01
状态：已确认并进入实施

## 1. 目标

同一个火山方舟真实 API Key 通过 New API 渠道向公司员工发放虚拟 Key，并允许每把虚拟 Key 使用以下模型：

- `doubao-seedance-2-5-260628`
- `doubao-seedance-2-0-260128`
- `doubao-seedream-5-0-pro-260628`

Seedance 2.0/2.5 保留现有的异步任务计费；Seedream 5.0 Pro 的文生图、图生图和图层拆分统一改成成功响应后按方舟返回结果计费，不做请求前预扣。

## 2. 已确认的业务决定

### 2.1 模型和密钥

- 公司维护一条或多条真实方舟渠道，员工只收到 New API 虚拟 Key。
- 当前阶段不为员工提供操作后台；管理员集中创建用户、虚拟 Key并查看日志和账单。
- 虚拟 Key 的模型白名单包含上述三个模型。

### 2.2 Seedance 计费

- Seedance 继续使用任务完成时方舟返回的真实 token 数结算。
- Seedance 2.5 沿用已经验收通过的规则。
- Seedance 2.0 按分辨率和是否包含输入视频执行阶梯规则。

### 2.3 Seedream 统一后付费

只对 `doubao-seedream-5-0-pro-260628` 启用该规则：

- 请求进入时只校验模型已配置，不创建预扣计费会话。
- 方舟调用失败时不收费。
- 方舟成功后，从响应的 `usage` 与 `data[].size` 计算本次真实费用，再执行一次钱包后扣。
- 文生图、图生图、图层拆分走同一条结算链路，差异只体现在单张输出价格。
- 后付费允许用户余额变成负数；这是“不阻断生成、完成后结算”的必然结果，符合当前内部管理场景。

## 3. Seedream 计费规则

### 3.1 输入图片

- 第 1 张免费。
- 从第 2 张开始，每张 `¥0.02`。
- 输入图片数量优先采用方舟响应的 `usage.input_images`；若响应缺失，则从请求的 `image`/`images` 字段推导。

### 3.2 普通生成（文生图、图生图）

- 单张输出不超过 `2,610,000` 像素：`¥0.30/张`。
- 单张输出超过 `2,610,000` 像素：`¥0.60/张`。

### 3.3 图层拆分

当请求 `layer_decomposition=true` 时：

- 单张输出不超过 `2,610,000` 像素：`¥0.15/张`。
- 单张输出超过 `2,610,000` 像素：`¥0.30/张`。

### 3.4 缺失数据的保守策略

- 输出数量优先采用方舟响应的 `usage.generated_images`，并与 `data` 实际条目数取较大值。
- 能解析 `data[].size` 时按真实像素分档。
- 方舟声明有输出、但某张输出没有可解析尺寸时，按该场景的高档价格计算，避免漏计费。
- 计算过程保存场景、输入数、输出数、低档数、高档数、是否使用保守兜底和人民币金额，供管理员日志复核。

## 4. 请求与响应兼容

- `layer_decomposition` 必须作为正式的可空布尔字段透传；使用指针以区分未传与显式 `false`。
- 方舟的 `usage.input_images`、`usage.generated_images` 必须被 DTO 解析。
- 原始图片响应继续原样返回给调用方，不改变 URL、尺寸或图层数组结构。

## 5. 计费链路

```text
虚拟 Key 请求
  -> New API 校验模型/渠道
  -> Seedream 标记为 postpaid，跳过预扣
  -> 方舟生成
     -> 失败：返回错误，不扣费
     -> 成功：解析 usage + data[].size
             -> 计算人民币成本
             -> 转换为 New API quota
             -> 从虚拟 Key 所属用户钱包后扣
             -> 写入使用日志和结构化计费明细
```

`ModelPrice` 在请求前只承担“该模型已配置、允许调用”的入口价格作用；成功响应后会被本次计算出的总人民币金额替换，且不会再乘请求中的 `n`。

## 6. 明确不做的范围

- 不实现 Seedream 预扣与冲正。
- 不新增数据库表或对账任务。
- 不从方舟控制台反查每次图片账单；以官方响应字段和官方公开价格计算。
- 不改变前端全局看板 UI。
- 不在本次自动测试中调用付费生成接口；真实方舟验收步骤单独列出，由拿到账号/密钥后执行。

## 7. 已知边界

- 后付费没有余额闸门，可能产生负余额。
- 极端情况下，如果方舟已经成功收费但 New API 进程在写本地结算前崩溃，本地账单可能遗漏。彻底解决需要持久化请求账本和对账任务，超出当前“一切从简”的范围。
- 当前后付费链路按钱包额度结算；不承诺订阅包模式的 Seedream 后付费一致性。

## 8. 验收标准

- 三个模型出现在方舟渠道及目标虚拟 Key 的模型列表中。
- `layer_decomposition=true/false` 均能保持原值透传。
- Seedream 请求前不扣额度；失败响应不扣额度；成功响应按规则一次性后扣。
- 文生图、图生图、图层拆分及尺寸缺失兜底均有单元测试。
- 日志能看到人民币费用和 Seedream 计费明细。
- 现有 Seedance/OpenAI/计费测试不回归。
