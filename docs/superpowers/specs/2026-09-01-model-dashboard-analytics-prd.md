# 公司模型数据看板统计与可视化优化 PRD

日期：2026-09-01

状态：已确认（2026-09-01）

适用页面：`/dashboard/models`

## 1. 背景

公司通过 New API 将火山方舟真实渠道封装为虚拟 Key，管理员需要在一个统一看板中查看所有员工、虚拟 Key 和模型的调用、费用、Token 与运行健康情况。

当前模型看板已经能够展示调用次数、人民币费用、Token、RPM、TPM、性能健康和模型图表，但存在以下问题：

1. 时间轴在有效时间点少于 7 个时，会用“最近 7 个时间桶”替换真实时间点，导致真实消费被汇总到顶部，却没有绘制在图表中。
2. “总数”实际累计的是计费日志事件，异步任务的预扣、补扣可能让同一个任务被重复计数。
3. “总 Token 数”没有纳入 Seedance 异步任务完成后返回的 actual tokens。
4. “总额度”文案容易被理解为账户总余额，实际表示所选时间范围的消费。
5. 平均 RPM/TPM 使用所选时间范围总量除以全部分钟数，低频集中调用时长期接近 0，缺乏实时监控价值。
6. 当前“性能健康”只包含同步请求性能数据，没有纳入异步视频任务，却以平台整体指标的形式展示。
7. 当前时间范围隐藏在筛选弹窗中，图表缺少缩放、拖动和明确的时间口径提示。
8. 完整 Model ID 过长，图例和悬浮信息不利于管理员快速阅读。

## 2. 产品目标

本次优化需要达成以下目标：

- 所有顶部统计数字具有明确、可复核且不重复的统计口径。
- 看板能够正确统计 Seedance、Seedream 以及未来语言模型的调用、最终消费与实际 Token。
- 管理员可以快速选择时间范围，并在稀疏数据和长时间范围下完整查看趋势。
- RPM/TPM 反映平台当前负载，而不是被长时间空闲稀释后的平均值。
- 性能健康直接按模型展示，统一呈现成功率与端到端耗时，不在界面上区分同步或异步模型。
- 页面默认使用人民币展示消费，并保持与现有系统计费口径一致。
- 修复和回填现有本地历史数据时不调用火山方舟，不产生额外费用。

## 3. 用户与权限

### 3.1 目标用户

- Root 管理员。
- 具有全局看板读取权限的普通管理员。

### 3.2 权限要求

- Root 与被授权管理员可以查看所有用户和虚拟 Key 的聚合数据。
- 管理员可以按用户名筛选数据，但不在本次新增部门或组织维度。
- 普通用户的个人看板不属于本次改造范围。
- 看板和接口不得返回真实上游 API Key 或完整虚拟 Key。

## 4. 页面信息架构

模型调用分析页面按以下顺序展示：

```text
模型调用分析
当前范围：最近 7 天 · 按天聚合
[今天] [24 小时] [7 天] [30 天] [自定义] [筛选] [偏好设置]

[总调用] [总消耗] [总 Token] [当前 RPM] [当前 TPM]

性能健康 · 最近 24 小时
整体摘要
按模型逐行性能

消费趋势图
模型调用趋势 / 调用次数分布 / 调用次数排行
```

移动端允许卡片换行，但不得通过横向溢出隐藏关键指标。

## 5. 顶部统计卡片

顶部保留 5 张卡片。前三张跟随页面所选时间范围，后两张使用固定的最近 5 分钟窗口。

### 5.1 总调用

显示所选时间范围内通过身份、Key、模型权限和基础参数校验，并实际进入上游调用或异步任务提交流程的请求总数。

统计规则：

- 同步请求以唯一 `request_id` 计数，每个请求只计一次。
- 异步任务以唯一 `task_id` 计数，每个任务只计一次。
- 预扣、补扣、退款、轮询和日志重试均不得增加调用次数。
- 本地鉴权失败、无权访问模型和未进入上游的参数校验失败不计入模型调用。
- 上游返回失败或异步任务终态失败仍计入总调用，并计入失败数。
- 主值显示总调用数，副文本显示成功数和失败数，例如“成功 19 · 失败 1”。
- 数据按请求或任务首次提交时间归属到时间桶；任务完成后只更新同一调用的状态、Token 和最终消费，不创建新的调用计数。

### 5.2 总消耗

原“总额度”改名为“总消耗”。

统计规则：

- 跟随所选时间范围。
- 显示调用最终结算后的人民币净消费。
- 异步任务按照任务最终结算金额统计，预扣不作为第二笔消费。
- 补扣和退款只调整同一调用的最终金额，不增加调用次数。
- 失败且完全退款的调用消费为 `¥0`。
- 管理员默认汇总所有用户和虚拟 Key；应用用户名筛选后只汇总目标用户。
- 卡片副文本显示“所选时段”。

### 5.3 总 Token

显示所选时间范围内所有调用最终返回并被系统记录的实际 Token 数。

数据来源：

- Seedance：任务完成响应中的 `tasks.data.usage.total_tokens`，若只有 `completion_tokens` 则使用有效的实际完成 Token。
- Seedream：同步响应 `usage` 中的 `total_tokens` / `output_tokens`。
- 语言模型：使用日志中的输入 Token 与输出 Token 合计。
- 同一个请求或任务只计一次，预估 Token 不与 actual tokens 同时累计。
- 失败且没有有效 usage 的调用计为 0 Token。
- 卡片跟随所选时间范围，不显示历史全量。
- 卡片悬浮明细按模型展示 Token，完整 Model ID 可复制。

Token 是调用规模指标，不直接等于费用。Seedream Token 不是其官方计费单位，明细中需要保留模型维度，避免管理员将不同模型 Token 当成统一价格单位。

### 5.4 当前 RPM

- 固定使用最近 5 分钟滚动窗口，不受页面时间筛选影响。
- 计算公式：最近 5 分钟进入模型调用流程的唯一请求/任务数除以 5。
- 每 30 秒自动刷新。
- 卡片标题显示“当前 RPM”，副文本显示“近 5 分钟”。
- 悬浮信息显示所选时间范围内的峰值 RPM 和峰值出现时间。

### 5.5 当前 TPM

- 固定使用最近 5 分钟滚动窗口，不受页面时间筛选影响。
- 计算公式：最近 5 分钟完成结算并获得实际 usage 的 Token 合计除以 5。
- 每 30 秒自动刷新。
- 卡片标题显示“当前 TPM”，副文本显示“近 5 分钟”。
- 悬浮信息显示所选时间范围内的峰值 TPM 和峰值出现时间。
- 异步任务只在获得 actual tokens 后计入，不使用提交阶段估算值。

## 6. 时间范围与聚合粒度

### 6.1 快捷时间范围

页面顶部常驻以下选项：

- 今天：本地时区当天 `00:00:00` 至当前时间。
- 24 小时：当前时间向前滚动 24 小时。
- 7 天：当前时间向前滚动 7 天。
- 30 天：当前时间向前滚动 30 天。
- 自定义：管理员选择开始与结束时间。

原有“29 天”改为“30 天”。

### 6.2 时间范围提示

页面必须始终显示当前范围和聚合粒度，例如：

```text
当前范围：2026-08-26 14:00 ～ 2026-09-02 14:00 · 按天
```

所有时间按照 `Asia/Shanghai` 展示。

### 6.3 自动聚合

- 今天、24 小时以及不超过 48 小时的自定义范围：按小时。
- 7 天、30 天以及超过 48 小时且不超过 90 天的自定义范围：按天。
- 超过 90 天的自定义范围：按周。
- 管理员仍可在筛选弹窗中手动覆盖粒度。

## 7. 时间轴与图表交互

### 7.1 时间点生成

- 时间轴必须覆盖完整所选范围。
- 数据库存在的真实时间桶必须全部保留。
- 无数据时间桶补 0，不得以最近若干时间点替换真实时间点。
- 稀疏数据仍需保持真实时间间距。
- 图表总计必须与相同筛选条件下的顶部总消耗或总调用一致。

### 7.2 X 轴交互

- 提供底部缩放滑块。
- 支持拖动滑块查看局部时间范围。
- 支持鼠标滚轮缩放。
- 支持拖动画布平移。
- 双击恢复完整时间范围。
- 缩放只改变可见范围，不重新定义顶部卡片统计范围。

### 7.3 悬浮信息

消费图表悬浮至少显示：

- 准确日期时间。
- 模型短名称和完整 Model ID。
- 调用次数。
- 人民币消费。
- 占当前时间桶总消费比例。
- Token 或图片生成张数（存在时）。

模型调用图表悬浮至少显示时间、模型、调用次数、成功数和失败数。

### 7.4 图例

- 默认显示短名称，例如“Seedance 2.5”“Seedance 2.0”“Seedream 5.0 Pro”。
- 悬浮或详情中显示完整 Model ID。
- 点击图例可以隐藏或恢复某个模型。
- 未配置短名称的新模型回退为完整 Model ID。

## 8. 性能健康

### 8.1 目标

性能健康用于回答平台当前是否可用、哪些模型失败、调用端到端耗时是否异常、是否存在运行中或疑似卡住的调用。

性能健康不跟随页面业务时间筛选，默认固定展示最近 24 小时，并提供 `1 小时 / 24 小时 / 7 天`切换。

### 8.2 当前整体状态

整体状态使用最近 15 分钟滚动窗口：

- 无调用：没有新的模型调用，使用灰色状态，不能显示为健康。
- 健康：存在已完成调用，且没有失败或疑似卡住调用。
- 注意：存在失败、疑似卡住调用或模型成功率明显下降。
- 故障：同一模型连续失败至少 3 次、所有可用渠道调用失败，或存在明确渠道不可用状态。

整体摘要显示：

- 成功数 / 总调用数与成功率。
- 失败数。
- 当前运行中数量。
- 疑似卡住数量。
- 最后更新时间。

成功率必须使用全部请求加权计算：`成功总数 ÷ 调用总数`，不得对各模型成功率做简单平均。

界面需要明确区分两个观察窗口：整体状态标识使用最近 15 分钟，用于判断“现在是否正常”；整体摘要和模型明细使用性能健康区域当前选择的 `1 小时 / 24 小时 / 7 天`，用于查看一段时间内的稳定性。

### 8.3 按模型逐行展示

页面不显示“同步请求”“异步请求”分类，直接按模型列出：

```text
Seedance 2.5       成功 15/15 · 100%   P50 2m10s   P95 3m25s
Seedance 2.0       成功 1/1 · 100%     P50 1m50s   P95 样本不足
Seedream 5.0 Pro   成功 3/4 · 75%      P50 50s     P95 55s
```

每行至少包含：

- 模型短名称。
- 状态标识。
- 成功数 / 总调用数。
- 成功率。
- P50 端到端耗时。
- P95 端到端耗时或“样本不足”。
- 当前运行中数量（非 0 时显示）。
- 最近一次失败时间和简短原因（存在时显示）。

点击模型行跳转到已应用模型和时间范围筛选的日志页面。

### 8.4 端到端耗时定义

不同模型统一使用“从平台接受调用到最终成功或失败”的端到端耗时：

- Seedream：请求开始到图片响应完成。
- Seedance：任务首次提交到最终成功或失败。
- 语言模型：请求开始到完整响应结束；流式模型使用完整输出结束时间。

P50 和 P95 只使用最终成功调用的端到端耗时样本，失败调用单独计入失败数和最近失败信息，不混入正常生成耗时分位数。P50 在存在至少 1 个成功样本时显示。P95 在存在至少 3 个成功样本时显示；少于 3 个显示“样本不足”。样本数小于 20 时，悬浮提示“小样本，仅供参考”。

### 8.5 疑似卡住任务

- 仅对尚未进入终态的调用判断卡住。
- 默认规则为连续 15 分钟没有状态或进度更新。
- 卡住规则应在后端集中定义，前端只展示结果。
- 卡住任务计入运行中，不计入失败，除非最终进入失败或超时终态。

### 8.6 不再展示的性能指标

移除统一的“Token/s 吞吐量”指标。图片、视频和语言模型的 Token 语义不同，统一吞吐量不能代表平台整体性能。未来可以只在语言模型详情中展示输出 Token/s。

## 9. 数据聚合与一致性

### 9.1 唯一调用记录

看板聚合必须以唯一调用为基础，而不是以计费日志事件为基础：

- 同步调用唯一键优先使用 `request_id`。
- 异步调用唯一键使用 `task_id`。
- 重试、轮询、补扣、退款必须关联同一唯一调用。
- 聚合写入和历史回填必须幂等，多次执行结果不变。

### 9.2 时间归属

- 调用次数按照首次提交时间归属。
- 同一调用的最终 Token 与最终消费回写到该调用首次提交时所在的时间桶。
- 调用尚未结束时，可以先显示调用数与运行中状态；最终 Token 和消费在结算后更新同一记录。
- 该规则保证同一个时间桶的调用、Token 和消费来自同一批调用。

### 9.3 实时性

- 顶部业务统计和图表至少每 60 秒可刷新。
- 当前 RPM/TPM 每 30 秒刷新。
- 页面显示最后更新时间。
- 提供手动刷新按钮。
- 手动刷新不得重复写入聚合数据。

- 修正现有 `quota_data` 中因预扣和补扣产生的重复调用计数。
- 回填仅访问本地 PostgreSQL，不调用火山方舟。
- 回填脚本必须支持 dry-run，输出将新增、更新和跳过的记录数量。
- 回填前后保留汇总对比文档。

## 11. 筛选与偏好设置

- 继续复用现有用户名筛选。
- 增加模型多选筛选。
- 快捷时间范围常驻，完整筛选保留在弹窗中。

- 用户手动选择的自定义范围在重新打开筛选弹窗时必须保留。
- 页面刷新后恢复管理员已保存的偏好设置。

## 12. 空状态、错误与降级

- 所选范围没有调用时，卡片显示 0，图表显示“所选时间范围内没有调用数据”。
- 性能健康最近 15 分钟没有调用时显示“无调用”，不能显示 100% 健康。
- 单个模型缺少 Token 不得阻止其他指标展示，明细显示“无 Token 数据”。
- P95 样本不足时明确显示“样本不足”。
- 聚合接口失败时显示错误状态和重试按钮，不保留可能过期的旧数字伪装为最新数据。
- 历史回填失败必须回滚本批次变更或保证下次幂等重跑。

## 13. 可访问性与响应式要求

- 所有图表交互均提供键盘可访问方式或等价的筛选控件。
- 颜色不是状态的唯一表达，成功、注意、故障和无调用必须同时显示文字或图标。
- 图表悬浮明细在移动端可通过点击查看。
- 完整数值可通过悬浮或点击查看，卡片不因缩写丢失精确值。
- 人民币、时间、百分比和数字格式遵循当前界面语言与本地化设置。

## 14. 验收标准

### 14.1 统计口径

1. 相同 `task_id` 存在预扣、补扣和退款事件时，总调用只增加 1。
2. Seedance任务完成后，总 Token 增加 actual tokens，而不是估算 Token。
3. 切换时间范围时，总调用、总消耗和总 Token 同步变化。
4. RPM/TPM 保持最近 5 分钟口径，不随业务时间范围改变。
5. 总消耗与最终结算金额一致，不重复累计预扣和补扣。

### 14.2 时间轴

1. 输入现有 5 个真实小时桶后，图表必须保留全部 5 个真实时间点。
2. 时间范围内无数据的桶补 0，但不得删除或移动真实数据。
3. 切换 24 小时、7 天和 30 天时自动使用正确粒度。
4. X 轴缩放和平移不会改变顶部卡片总计。
5. 图表总计与相同筛选条件的顶部卡片一致。

### 14.3 性能健康

1. 当前数据应同时出现 Seedance 2.5、Seedance 2.0 和 Seedream 5.0 Pro 行。
2. 使用本 PRD 基准快照验收时，Seedream 显示成功 `3/4 · 75%`。
3. Seedance成功任务必须纳入成功率和端到端耗时。
4. 整体成功率按全部调用加权，不对模型成功率做简单平均。
5. 最近 15 分钟无调用时显示“无调用”。
6. 少于 3 个完成样本时 P95 显示“样本不足”。

### 14.4 历史回填

1. dry-run 不修改数据库。
2. 正式回填后重复执行一次，第二次不得新增或重复累计数据。
3. 回填后在包含全部当前数据的范围内，总 Token 为 `4,226,311`。
4. 回填不访问任何付费模型接口。
5. 回填前后人民币总消耗保持一致。
