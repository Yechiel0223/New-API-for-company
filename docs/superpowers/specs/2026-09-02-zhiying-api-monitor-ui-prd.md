# 智颖API监控企业上线版 UI 裁剪 PRD

日期：2026-09-02  
状态：P0 需求确认  
产品名称：智颖API监控

## 1. 背景

当前系统基于 New API，默认包含官网首页、顶部导航、聊天/游乐场、文档、定价、系统设置、插件、订阅等通用平台能力。

本项目当前上线目标是公司内部使用，不是对外宣传型 API 平台。核心场景是：

- 员工使用管理员发放的虚拟 API Key 调用模型；
- 管理员/老板查看用户、Key、渠道、日志、用量、账单和模型调用看板；
- 界面需要简洁、稳定、专业；
- 页面不应再显著出现 New API 品牌和无关功能入口。

因此需要做一版企业内部上线 UI 裁剪。

## 2. 核心原则

本次改造是 UI 层隐藏和品牌替换，不是物理删除功能。

要求：

- 不删除后端接口；
- 不删除数据库表；
- 不改变计费逻辑；
- 不改变渠道逻辑；
- 不改变虚拟 Key 调用方式；
- 不影响 Seedance/Seedream 已验收链路；
- 被隐藏的能力未来如需恢复，可以通过重新打开 UI 入口或直接访问内部路由维护。

## 3. 产品名称与品牌

系统名称统一为：

```text
智颖API监控
```

页面显著位置不再展示：

```text
New API
New-API
NewAPI
默认 New API logo
```

影响范围包括：

- 浏览器标题；
- 登录页标题；
- 左上角品牌；
- 页脚；
- 默认系统名称；
- 首页文案；
- 空状态或基础页面中的默认品牌露出。

第一版品牌方案采用方案 A：

```text
只显示文字：智颖API监控
```

不新增复杂 logo，不引入外部图片资源。

## 4. 登录与访问逻辑

### 4.1 未登录状态

用户访问网站时，如果没有登录态，直接进入简洁登录页。

登录页保留：

- 标题：智颖API监控；
- 用户名或电子邮件输入框；
- 密码输入框；
- 登录按钮。

登录页隐藏：

- 官网首页；
- 营销大标题；
- API 示例代码卡片；
- 开始使用；
- 查看定价；
- 文档入口；
- 第三方应用支持；
- 忘记密码；
- 注册入口；
- 第三方登录；
- 复杂背景图；
- 外部字体链接；
- New API 品牌露出。

### 4.2 已登录状态

用户已有登录态时，访问根路径直接进入：

```text
/dashboard/models
```

即“模型调用分析”页面。

登录成功后默认也进入：

```text
/dashboard/models
```

## 5. 顶部导航裁剪

登录后的后台顶部导航需要极简化。

隐藏：

- 主页；
- 控制台；
- 文档；
- 关于；
- 搜索栏；
- 系统公告入口；
- 主题设置；
- 语言切换。

建议保留：

- 用户头像/账号菜单；
- 退出登录入口。

如果用户头像区域仍显得复杂，后续可继续弱化，但本版不强制删除退出登录能力。

## 6. 左侧栏裁剪

### 6.1 隐藏聊天分组

隐藏整个“聊天”分组：

- 游乐场；
- 聊天。

### 6.2 常用分组

隐藏：

保留：

- 使用日志；

### 6.3 数据看板

数据看板只保留：

- 模型调用分析；
- 用户统计。

隐藏：

- 分流。

### 6.4 个人分组

保留：

- 钱包；
- 个人资料。

### 6.5 管理员分组

保留：

- 渠道；
- 用户；
- 系统信息。

隐藏：

- 模型；
- 兑换码；
- 订阅；

### 6.6 系统设置

隐藏整个“系统设置”入口。

要求：

- root UI 中不展示；
- 老板/管理员 UI 中不展示；
- 普通用户 UI 中不展示；
- 只是 UI 不展示，不删除底层能力。

## 11. 推荐实施顺序

1. 品牌替换：浏览器标题、系统默认名称、左上角文字和明显 New API 文案。
2. 登录页重做：未登录直接显示极简登录页，隐藏忘记密码、注册和第三方入口。
3. 登录跳转：已登录访问根路径和登录成功后默认进入 `/dashboard/models`。
4. 顶部导航裁剪：隐藏主页、控制台、文档、关于、搜索、公告、主题、语言。
5. 侧边栏裁剪：仅保留本 PRD 指定菜单。
6. 数据看板裁剪：只保留“模型调用分析”和“用户统计”。
7. 验证：前端构建、登录流程、侧边栏显示、核心页面可访问。

## 12. 风险与注意事项

- 本次隐藏系统设置入口，但不删除功能；root 后续如需维护系统设置，可能需要通过直接 URL 或临时恢复入口。
- 前端隐藏不等于权限控制。若未来需要安全层面的严格禁止访问，应再补后端权限控制。
- 当前仍使用临时 IP 和 HTTP，正式给更多员工使用前，建议补域名和 HTTPS。
